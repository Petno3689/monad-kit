# Шаблон тикета

Первая строка: `Model: Haiku|Sonnet|Opus — <почему эта модель>`

## GOAL
Что должно появиться после тикета, одним абзацем.

## FACTS (измерено, не перемерять)
Проверенные ревьюером факты: версии, адреса, параметры, числа.

## SCOPE
Что трогать и чего не трогать (список файлов; что только читать).

## CHANGES
Пронумерованный список изменений по файлам.

## CHECKS
Команды, которые нужно выполнить, и ожидаемый результат.

## REPORT
- Код возврата и последняя строка вывода дословно (forge build, forge test, npm test, npm run build, npm run lint).
- Список созданных и изменённых файлов.
- Отклонения от тикета, каждое с причиной.

## STOP IF
Условия, при которых нужно остановиться и сообщить, а не продолжать.

---

## Обязательные строки в каждом тикете

Скопировать в конец тикета без изменений:

- Разрешено: forge build, forge test, npm install, npm test, npm run typecheck, npm run build, npm run lint, git только чтение (status, diff, log, show).
- Запрещено: всё, что меняет индекс или историю git; любой deploy или broadcast; любые ключи и keystore.
- Падает тест — чини код, а не тест (исключение: ожидания, названные в тикете).
- Не подбирай параметры и эталонные значения, чтобы тест прошёл — сообщи об этом.
- Никакого assembly в contracts/src.
- Golden-векторы получаются только скриптами-генераторами, не руками.
- Доказательство запуска — код возврата и последняя строка вывода дословно.
